# Architecture Overview

## System Architecture

Draftline is a **desktop application** built on [Wails](https://wails.io/), which embeds a Go backend with a web frontend.

```
+-----------------------------------------------------------------------+
|                           DRAFTLINE APP                                |
|                                                                        |
|  +---------------------------+     +--------------------------------+  |
|  |       GO BACKEND          |     |        REACT FRONTEND          |  |
|  |                           |     |                                |  |
|  |  +---------------------+  |     |  +------------------------+   |  |
|  |  |      app.go         |  |<--->|  |      App.tsx           |   |  |
|  |  | (Wails bindings)    |  |     |  | (Main layout)          |   |  |
|  |  +---------------------+  |     |  +------------------------+   |  |
|  |            |              |     |             |                 |  |
|  |  +---------v-----------+  |     |  +----------v-------------+   |  |
|  |  |    import.go        |  |     |  |     bookStore.ts       |   |  |
|  |  | (EPUB/DOCX import)  |  |     |  | (Zustand state)        |   |  |
|  |  +---------------------+  |     |  +------------------------+   |  |
|  |            |              |     |             |                 |  |
|  |  +---------v-----------+  |     |  +----------v-------------+   |  |
|  |  |    setup.go         |  |     |  |    Components/         |   |  |
|  |  | (Claude Code setup) |  |     |  | EditorPanel, etc.      |   |  |
|  |  +---------------------+  |     |  +------------------------+   |  |
|  +---------------------------+     +--------------------------------+  |
|                |                                  |                    |
+----------------|----------------------------------|--------------------+
                 v                                  v
        +------------------+              +------------------+
        |   FILE SYSTEM    |              |   AI PROVIDERS   |
        | .draftline files |              | Claude, GPT, etc |
        +------------------+              +------------------+
```

## Component Communication

### Wails Bindings
Go methods on the `App` struct become callable from JavaScript:

```go
// Go (app.go)
func (a *App) SaveBook(book BookData) SaveResult { ... }
func (a *App) RewriteText(html, mode, opts string) AIRewriteResult { ... }
```

```typescript
// TypeScript (generated by Wails)
import { SaveBook, RewriteText } from '../wailsjs/go/main/App'

const result = await SaveBook(bookData)
```

### Event System
Backend can push events to frontend:
```go
// Go
runtime.EventsEmit(a.ctx, "ai:token", token)
runtime.EventsEmit(a.ctx, "setup:progress", message)
```

```typescript
// TypeScript
EventsOn("ai:token", (token) => { /* streaming AI response */ })
```

## Data Flow

### Saving a Book
```
User clicks Save
       |
       v
bookStore.saveBook()
       |
       v
Wails: SaveBook(bookData)
       |
       v
Go: createZipArchive()
  - manifest.json
  - body/*.html
  - story_bible.json
  - etc.
       |
       v
Write to disk: book.draftline
```

### AI Rewrite Flow
```
User selects text + clicks rewrite
       |
       v
bookStore.rewriteWithAI()
       |
       v
Wails: RewriteText(html, mode, styleOpts)
       |
       v
Go: buildPrompt() + callProvider()
       |
       +-- Claude Code CLI (subprocess)
       +-- Anthropic API (HTTP)
       +-- OpenAI API (HTTP)
       +-- etc.
       |
       v
Stream tokens via ai:token event
       |
       v
Frontend shows diff for review
```

## State Architecture

### Zustand Store Pattern
```typescript
// bookStore.ts - simplified
interface BookStore {
  // State
  book: BookData | null
  currentChapter: number
  isDirty: boolean

  // Actions
  loadBook: (path: string) => Promise<void>
  saveBook: () => Promise<void>
  updateChapter: (content: string) => void

  // AI Actions
  rewriteSelection: (mode: string) => Promise<void>
}
```

### Why Single Store?
- Book data is deeply interconnected
- Chapters, characters, beats all relate
- Simpler than prop drilling or context
- Easy persistence (save entire state)

## The .draftline Format

A renamed ZIP file containing JSON and HTML:

```
book.draftline (ZIP)
├── manifest.json          # Metadata, chapter index
├── body/
│   ├── 000.html          # Chapter 1
│   ├── 001.html          # Chapter 2
│   └── ...
├── front_matter/
│   └── ...
├── back_matter/
│   └── ...
├── story_bible.json      # Characters, plot notes
├── beat_sheet.json       # Story structure
├── foreshadowing.json    # Plant/payoff tracking
└── knowledge_matrix.json # Secrets tracking
```

See [Data Model](../data-model/README.md) for detailed schemas.

## AI Integration Architecture

### Provider Abstraction
All AI providers follow the same pattern:
1. Build system prompt (with style mixer, banned words, etc.)
2. Build user message (content + context)
3. Call provider API
4. Stream or return result

### Claude Code Special Case
Claude Code can authenticate two ways:
1. **OAuth** (via `claude` CLI) - spawns subprocess
2. **API Key** (stored in credentials) - direct HTTP calls

The app checks credentials and chooses the faster path automatically.

See [AI Features](../ai/README.md) for prompt engineering details.
